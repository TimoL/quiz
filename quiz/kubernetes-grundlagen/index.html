1. Was ist Kubernetes?

Kubernetes ist eine Open-Source-Plattform zur Orchestrierung containerisierter Anwendungen. Ein Container verpackt eine Anwendung mit ihrer Laufzeitumgebung. Kubernetes koordiniert, auf welchen Maschinen solche Container laufen, wie viele Kopien benötigt werden und wie Änderungen kontrolliert ausgerollt werden.

Stell dir eine Webanwendung vor, die mehrfach laufen soll. Statt jede Instanz einzeln auf einem Server zu starten und nach Ausfällen händisch zu ersetzen, beschreibst du einen gewünschten Zustand. Kubernetes versucht fortlaufend, diesen Zustand herzustellen und zu erhalten.

Quelle: Kubernetes Overview

2. Wofür braucht man es?

Es hilft beim wiederholbaren Betrieb von Anwendungen: Pods verteilen, Replikate verwalten, Versionen schrittweise aktualisieren und Netzwerkzugänge bereitstellen. Eingerichtete Autoskalierung kann die Zahl der Replikate anhand von Lastmetriken anpassen. Mehr Replikate bedeuten allerdings nicht automatisch mehr verfügbare Server.

Eigene Einordnung: Bei vielen Diensten, häufigen Updates und mehreren Betriebsverantwortlichen kann diese gemeinsame Steuerung nützlich sein. Für wenige einfache Anwendungen auf einem einzelnen Rechner kann ein einfacheres Container-Setup genügen. Kubernetes ist kein Selbstzweck: Der Nutzen muss den Aufwand für Betrieb und Fehlersuche rechtfertigen.

Grundlagen: Overview und Horizontal Pod Autoscaling. Die Abwägung ist eine Orientierung, keine allgemeine Pflichtempfehlung.

3. Welche Bausteine gibt es?

Cluster
Das Gesamtsystem aus Control Plane und Maschinen mit Worker-Rolle.
Control Plane
Steuert den Cluster. API-Server, Controller, Scheduler und der Zustandsdatenspeicher etcd übernehmen unterschiedliche Aufgaben.
Node
Eine ausführende Maschine, virtuell oder physisch. Dort laufen kubelet und Container-Runtime.
Pod
Kleinste bereitstellbare Einheit: ein oder mehrere eng zusammengehörende Container mit gemeinsamem Netzwerk und gegebenenfalls gemeinsam genutztem Speicher.
Deployment
Beschreibt für geeignete Anwendungen gewünschte Pod-Vorlage, Replikate und Update-Verhalten; verwaltet dafür ReplicaSets.
Service
Stabiler Netzwerkzugang zu einer ausgewählten Gruppe von Pods – unabhängig davon, welche einzelnen Pods gerade existieren.

Quellen: Komponenten, Pods, Deployments, Services.

4. Wie wird daraus eine laufende App?

Konfiguration → API-Server → Controller → Pods → Scheduler → Node mit kubelet + Runtime
  1. Du übermittelst ein Deployment, zum Beispiel mit dem Ziel „drei Replikate dieser Webanwendung“.
  2. Die API nimmt die Konfiguration entgegen; der Cluster-Zustand wird gespeichert.
  3. Deployment- und ReplicaSet-Controller veranlassen die notwendigen Pod-Objekte.
  4. Der Scheduler ordnet neue Pods geeigneten Nodes zu.
  5. Das kubelet des jeweiligen Nodes sorgt mit der Runtime dafür, dass die beschriebenen Container ausgeführt werden.
  6. Die Regelkreise bleiben aktiv: Fehlt eine gewünschte Replik, wird Ersatz veranlasst. Fehlen Kapazität oder andere Voraussetzungen, kann ein Pod trotzdem nicht starten.

Die Pfeile sind eine Lernvereinfachung. Die Komponenten kommunizieren über die Kubernetes-API; es ist keine einmalige direkte Befehlsübergabe von Komponente zu Komponente.

Quellen: Komponenten und Controller und Regelkreise.

5. Was passiert bei Problemen?

Readiness: Ist die Anwendung bereit für Anfragen? Schlägt die Prüfung fehl, soll der betroffene Pod keinen regulären Service-Traffic erhalten. Liveness: Muss ein Container wegen eines ungesunden Zustands neu gestartet werden? Das sind unterschiedliche Fragen – und Prüfungen müssen sinnvoll konfiguriert sein.

Updates: Ein Rolling Update ersetzt alte Pods schrittweise. Das hilft beim kontrollierten Versionswechsel, ist aber keine Garantie für unterbrechungsfreien Betrieb.

Quellen: Probes und Deployments.

6. Wo liegen die Grenzen?

Kubernetes schreibt und repariert nicht deine Anwendungslogik. Sicherheitsregeln, Überwachung, Backups und ein tragfähiges Cluster-Design bleiben Aufgaben des Betriebs. Persistenter Speicher ist kein Backup. Ein als Base64 dargestelltes Secret ist nicht dadurch verschlüsselt.

Quellen: Was Kubernetes nicht ist, Persistent Volumes, Secrets.
